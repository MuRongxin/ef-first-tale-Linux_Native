# 原生存档 v1：使用与实现（2026-10-27）

## 使用

运行严格剧本后，在对白显示完成或选项出现时：

- **F2**：快速保存，原子替换当前快速存档。
- **F3**：读取快速存档；完整校验新会话后再替换当前游戏。

```bash
cd "/home/lrxin/Ef_Linux/ef - the first tale"
cmake --preset dev
cmake --build --preset dev
./build/dev/ef_native --content content --script scr/test.sc
```

默认文件为 `$XDG_DATA_HOME/ef-native/saves/quick.json`；环境变量未设置或为相对路径时，回退 `$HOME/.local/share/ef-native/saves/quick.json`。存档与 `content/` 分开，不修改原游戏目录。

指定文件及重启恢复：

```bash
./build/dev/ef_native --content content --script scr/test.sc \
  --save-file work/saves/my-progress.json

./build/dev/ef_native --content content --load-save work/saves/my-progress.json
```

`--load-save` 自带剧本和 timing 变体，不与 `--script`、`--start-line`、`--text-preview` 或其它变体覆盖同时使用。未另设 `--save-file` 时，F2/F3 继续使用启动时的 `--load-save` 文件；否则使用显式指定的快速存档文件。普通游玩不需要 `--silent`。

单文件入口继续保留；100 个普通槽位、9 个快速槽轮换、槽位列表和启动读档现已接入，见 [槽位指南](SAVE-SLOTS-20261027.md)。窗口存读档菜单与原子缩略图已接入，见 [窗口菜单指南](SAVE-MENU-RUNTIME-20261028.md)；自动存档与完整原版菜单外观仍待实现。

## 可以保存的时机

保存支持：

- 手动推进且已显示完整的对白；选项菜单；
- 已稳定的背景、角色、裁切、色调层及待用的 frame/transition 状态；
- 持续雪花、Cutin、WScroll2、非阻塞滚动和取景器计时；
- 正在播放的语音、BGM、SE/SE2，以及仍在淡出的旧音轨。

逐字未完成、自动推进、禁用手动操作、等待指令、转场、震屏、阻塞滚动、消息窗淡化和视频播放期间不保存。这些时机保存会提示重试，原文件不会被改写。存档捕获的是原生运行时已经建立的状态；`--start-line` 开发入口没有此前剧情状态，不能把从该入口保存的文件当作正常路线的完整状态。

F3 读取经过验证的存档可以替换当前会话，包括停止当前播放器；读档失败则保留当前会话。字体偏好、窗口大小及 4×/8× 档位是用户设置，不从剧情存档恢复；同一存档可在不同窗口状态下使用。

## 格式与定位

文件是独立的 **UTF-8 JSON**，格式标记 `ef.save`、版本 `1`。它不使用原版 GBK/zlib `.sav`，不存 Windows 地址、原 exe 指针、纹理或 PCM 数据，也不需要 PAZ 或原游戏目录。

| 顶层字段 | 内容 |
|---|---|
| `format` / `version` | `ef.save` / 整数 1；未知版本拒绝读取 |
| `created_unix` | 保存时的 Unix 秒时间戳 |
| `binding` | 全部 JSON 剧本的 `json_sha256`、场景模板及消息窗布局标识 |
| `vm` | 当前程序、e/j、锚点、局部/全局变量、手动控制状态、文字速度与当前对白 |
| `presentation` | 虚拟坐标场景、待用帧/材质/转场、持续特效、非阻塞滚动、取景器及音轨状态 |
| `message_ui` | 当前面板、NVL 前文与当前段、说话人字节锚点；未接导入布局时为 null |

ID 中保留的 `.sc` 后缀仍是逻辑名称，不代表读取 SC 文件。对白锚点由 **程序 ID + 来源剧本 ID + L0** 标识，并保存物理行号，用来区分同一 L0 的多段 NVL 对白。读档在当前已编译程序中重新寻找锚点，再恢复其后的执行位置；不把以前的编译指令下标当作长期定位协议。选项锚点使用程序、来源剧本与物理行，选项及跳转标签重新从剧本生成。

当前对白直接校对包内原文、姓名、语音和来源，恢复时保持完整显示，不重放变量赋值或此前命令。局部变量跨 `.chain` 的行为保持不变。

音轨保存资源 ID 和源哈希、原始采样率下的帧位置、loop、gain/pan、目标增益和剩余淡化帧等信息。恢复只重新解码仍活跃的音轨，并恢复 mixer 状态；不从剧本开头回放，不重新触发当前对白语音。雪花保留粒子及随机种子，Cutin/WScroll2 保留各自时钟，取景器保留逻辑计时。

NVL 页保存此前已累计的文字、当前段和说话人位置。JSON 文字的字面反斜杠通过 `Message.plain_text` 传递，避免把已经编译完成的 `\w` 等字面文字再按旧 SC 控制码解释。暂停提示图标的动画相位重新开始，不属于剧情进度。

存档可带固定 100×75 的可选 `thumbnail` 字段（RGB8 hex），与状态同对象原子发布；旧档不含此字段仍可读取。协议与截图范围见 [窗口菜单指南](SAVE-MENU-RUNTIME-20261028.md)。

## 兼容与失败处理

首版采用保守兼容策略：保存时记录全部剧本源哈希和布局标识，读档必须一致。单纯改变 JSON 索引文件名、窗口档位或字体偏好不影响兼容；改变任一剧本内容或消息布局会拒绝旧档，不自动猜测新位置。自制旧预览包缺少 `json_sha256` 时应通过当前导入器重新生成包。

活动音频资源的源哈希也须一致。所有图片及音频 ID 都经 `content/` 解析，存档不能指定包外媒体路径。

文件最大 16 MiB，拒绝重复键、超过 64 层的 JSON、错误类型、NUL、越界数值、无效 UTF-8、缺失/歧义锚点、不一致的页面及音轨状态。场景层、雪粒子、变量和 NVL 页分别有数量/长度限制。

写入先在目标同目录生成临时文件，写完并同步，再原子替换。序列化、大小检查或发布前写入失败不会截断旧档。读档在新建且未接音频设备的候选会话中恢复；完成剧本/布局、媒体和字体校验、必要图片预加载及新音频输出准备后才提交。提交时先停止旧播放器/音频回调，再销毁旧会话，并重置画面合成缓存，避免悬空 mixer 引用或旧转场画面。

这不是防篡改签名格式。版本及资源绑定用于避免误恢复不兼容数据，不承诺支持手工改写任意内部字段。

## 验证与复现

```bash
ctest --preset dev
ctest --preset asan

# 合成包的真实键盘/像素检查，需 xvfb、xauth、libxtst6，不需要 Openbox
xvfb-run -a python3 tests/save_smoke.py --binary build/dev/ef_native

# 真实内容的开发检查：在第 5 条可保存对白处写入文件
./build/dev/ef_native --content content --script scr/106_01.sc \
  --trace-messages 5 --text-speed 0 --save-file work/save-verification/106.json

# 重启恢复并继续 20 条对白；计数包含当前保存的对白
./build/dev/ef_native --content content --load-save work/save-verification/106.json \
  --trace-messages 20
```

`--trace-messages` 配合 `--save-file` 仅在最后一条指定对白处保存；若该处属于自动推进或其它不可保存时机，就报错，不能默默换到另一条。无头检查快进时钟、静音，不代替画面/声音保真对照。

本机最终测试：dev **33/33**、ASan **23/23** 通过，独立资源验证 PASS / 失败 0。启用 FFmpeg 的构建也通过相同的 F2/F3、失败隔离和 NVL 像素界面回归；这项检查不代表在电影播放中保存。

回归包含：重复 L0 的第二段准确定位、NVL 前文及字面反斜杠像素一致、选项与跨文件变量延续、音频位置和交叠淡化、雪花/Cutin/WScroll2、取景器与非阻塞滚动的后续状态一致；错误版本、源哈希、锚点、数值、页面及媒体状态拒绝；写入失败保留旧文件。

真实界面测试通过 F2/F3 完成保存和恢复，并分别制造版本损坏及所需图片加载失败，确认当前会话仍可推进和选择。测试仅使用合成图片/剧本，不提交游戏数据。

本机真实包验证覆盖基础 e/j、开场雪花、全屏消息页和取景器五个保存点，分别重启恢复后连续 20 条消息通过，共 100 条。记录保存在本地 `work/save-verification/`；这些是片段恢复测试，不等同于在此前 112 条首次游玩路线的每一步都做存档复跑。
