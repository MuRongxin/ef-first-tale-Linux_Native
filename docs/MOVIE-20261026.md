# `.movie` 指令取证与实现方案（2026-10-26）

目标：原版 `ef_first_AA.exe`（PE32/i386）。本记录只含静态反汇编观察与移植方案，不含游戏素材；
可复现的反汇编摘录/字符串地址在本地 `work/re/movie-20261026/`（work 不入库）。

## 1. 结论摘要

- `.movie` 是**阻塞式全屏/矩形视频播放**：播放期间脚本暂停，播完（或在允许中断时被跳过）后继续。
- 参数：`<id> <file> [width] [height] [flag] [x] [y]`（至少 4 个）；默认 `width=800`、`height=600`、
  `flag=true`、`x=y=0`；`flag` 观察语义为“**允许中断/跳过**”（`f`/`0` 不可跳过，`t`/`1..9`/缺省可跳过）。
- 文件来自 `mov.paz`（第 10 个归档读取器 slot9），按扩展名 `.mpg/.mpeg/.avi` 走 DirectShow
  （MPEG splitter/decoder、AVI splitter、Video Renderer/VMR7、Sound Renderer）。
- `id` 字段被解析保存但**不参与播放**（Execute 未读取）；语料中的 `10000/10001/…` 暂视为回放/存档元数据。
- `.movie2` 命令类存在（对象 0x98），语料未使用，本轮未展开。

## 2. 命令对象与参数（观察）

| 项 | 值 |
|---|---|
| 命令名 | `.movie` @ `0x578588`；注册点 `0x4cb3c8` |
| CommandMovie | 对象 0x78；构造 `0x4ec7b0`，vtable `0x576a2c`；Parse `0x4ec3a0`；Execute `0x4ec850` |
| 字段 | `+0x44` id、`+0x48` 文件名、`+0x64` w、`+0x68` h、`+0x74` flag、`+0x6c` x、`+0x70` y |

Parse（`0x4ec3a0`）要求 ≥4 参数；第 5 参数 flag 的取值规则：首字符 `1..9`/`t`/`T` → true，
`0`/`f`/`F` → false，缺省/其它 → true；第 6/7 参数为可选 x/y。
Execute（`0x4ec850`）只传递 `(文件名, flag, w, h, x, y)` 给场景/播放入口 `0x4db670`，
**不读取 `+0x44` id**。

## 3. 播放链路（观察）

1. `0x4db670`：清理当前场景 → 取 **mov.paz 读取器（slot9，`0x5e1738`）** → `0x4fd820`
   （用读取器 vtable+0x10 检查文件，失败返回 false）→ `0x4fcda0` 启动全局播放器 `0x5aa320`。
2. `0x4fcda0`：保存目标矩形字段（`+0x18c..+0x198`），按扩展名选 DirectShow 分支
   （`.mpg/.mpeg` / `.avi`；其它扩展名失败），用 `CFileStream`（vtable `0x575a10`）
   把 PAZ 读取器包装成流，建立 filter graph（含重试/降级）。
3. 播放：`0x4fc9e0` 为播放消息泵/完成检查循环；`0x4fc3b0` 按目标矩形把视频帧画到游戏画面
   （主循环在 movie active 时调用它并暂停脚本）。
4. 结束/中断：`0x4fc750` 释放接口并把 `0x5aa320` 首字节清 0；中断输入且 **flag≠0** 时
   写配置键 `movieInterrupted`（`0x5759d8`）后释放，flag=0 时跳过中断分支继续播放。
5. 阻塞证据：主循环 movie-active 分支（`0x4bf368` 起）在播放中不推进脚本；
   `0x414c50` 是“movie active”标志 getter；手册自动存档事件也列有 “When A Movie Plays”。

DirectShow 字符串证据：`VMR7`（`0x57590c`）、`Sound Renderer`（`0x575918`）、
`MPEG-I Stream Splitter`（`0x575938`）、`MPEG Video Decoder`（`0x575968`）、
`MPEG Audio Decoder`（`0x575990`）、`Video Renderer`（`0x5759b8`）；
音频采样率常量 `0xbb80`=48000。

## 4. 移植实现方案

现状：content 已把 4 个视频导入为 `mov/<原名>`（`op_logo.mpg`、`ef_first_sound.avi`、
`ef_ED_sound.avi`、`ed_moji_test.avi`），包内为 H.264 MKV（3840×2880，约 23.3–24 fps）。
渲染器目前没有视频管线。

建议分两步：

1. **指令语义/状态机先行**（不依赖新库）：
   - Presentation 解析 `.movie` 的 7 参数/默认值/flag；把待播影片登记为阻塞项；
   - 脚本在影片播放期间暂停，结束/跳过（flag 允许时）后继续；
   - 缺失文件给出明确诊断（原生是静默失败，但移植保持严格模式更利于发现内容问题）。
2. **视频/音频管线**：
   - 依赖 FFmpeg：需要 `libavcodec-dev libavformat-dev libavutil-dev libswscale-dev
     libswresample-dev`（本机仅有运行库 .so，无开发头文件；这是当前实现阻塞项）；
   - 解码 H.264 → RGBA 纹理，按 `(x,y,w,h)` 画到 800×600 逻辑画布，复用 4×/8× 物理放大；
   - 音频重采样到 48000 后送入现有 mixer/SDL 输出，按 PTS 同步；
   - 跳过：`flag=true` 时按键/点击立即结束（对应原生 movieInterrupted 路径）。
3. 测试：参数/flag 默认值的纯函数测试；阻塞状态机测试；渲染测试用注入的假解码器；
   真实视频可用系统 ffmpeg 生成极短夹具（CI 无 ffmpeg 时跳过）。

## 5. 实现注意/差异

- 原生用 DirectShow 自行弹窗/渲染；移植按“解码帧铺到目标矩形”实现，不模拟 DirectShow
  的窗口/焦点/缩放细节。
- 原生 `.movie` 失败（文件缺失/扩展名不支持）会静默清场景后继续；移植暂按严格诊断处理。
- `id` 暂保存不参与播放；若后续实现影片回放/已读登记，再按回放模块取证。

## 6. 移植实现（2026-10-26）

已落地（本提交）：

- `Presentation`：解析 `.movie`（4~7 参数、默认值/flag/x/y），记录 `MovieRequest`，清空并覆盖当前
  场景，`busy()` 保持 true 直到应用层报告完成；构建时没有 FFmpeg 则严格报
  “.movie requires FFmpeg movie playback support”。
- `src/video/movie_player.*`：FFmpeg 解码 H.264/MPEG + AAC；视频帧经 sws_scale 铺到 `(x,y,w,h)`
  逻辑矩形（RGBA，顶层纹理），音频经 swresample 转 48 kHz 立体声 float 送入现有 SDL 输出；
  有音频时以设备已播放采样数作为主时钟（视频跟随音频），无音频/静音时用墙钟；文件结束
  或被跳过时释放并恢复脚本。
- `AudioOutput`：新增受控的电影音频环形缓冲（2 s，48 kHz 立体声），回调与现有 mixer 混合；
  电影开始/结束/跳过时复位，避免残留。
- `Renderer::movie`：不透明帧绘制（矩形外黑底）、纹理复用 `glTexSubImage2D`。
- `Application`：检测到 `MovieRequest` 时创建播放器，逐帧 `update`，完成后 `finish_movie()`；
  播放期间跳过普通 stage/UI/文字渲染；可跳过影片（flag=true）收到按键或左键点击立即结束，
  不可跳过影片忽略这些输入（窗口关闭仍有效）。
- 依赖：CMake 自动探测 FFmpeg 开发头/库（可用 `-DEF_FFMPEG_ROOT=...` 指向本地 sysroot）；
  本机无 dev 包时构建仍成功、`.movie` 禁用。Ubuntu 安装：
  `sudo apt-get install libavcodec-dev libavformat-dev libavutil-dev libswscale-dev libswresample-dev`。

验证：

- 单元/状态：`tests/presentation_tests.cpp` 覆盖 `.movie` 参数/默认值/flag/x/y、阻塞与完成握手、
  无 FFmpeg 时严格拒绝；`ef_presentation_tests` PASS。
- 渲染：`tests/movie_render_tests.cpp` 验证目标矩形、矩形外黑底、纹理复用；`movie_render` PASS。
- 解码：`tests/movie_player_tests.cpp` + `tests/movie_decode_smoke.py` 用 ffmpeg 生成短夹具，
  验证解码/缩放、静音时钟走完、skip 幂等；FFmpeg 构建的 `movie_decode` PASS。
- 完整测试：dev 预设 26/26（movie_decode 只在 FFmpeg 可用时注册）、ASan 18/18；
  FFmpeg 启用构建 27/27。
- 真实素材（FFmpeg 构建）：
  - `scr/opening.sc`（`.movie 0 op_logo.mpg 800 600 f`）：`[movie] start/finished` 后脚本结束，
    `--frames 20 --screenshot` 截帧确认 Musica logo 正确按 800×600 渲染、矩形外黑底；
  - `scr/movie.sc`（`ef_first_sound.avi … t`，音频路径 + SDL dummy 驱动）：播放完成、脚本结束；
  - 无声/有声两条路径均无脚本推进错序（电影结束前脚本保持暂停）。

与原生差异/限制：

- 用 FFmpeg + GL 纹理替代 DirectShow 的窗口/焦点/Overlay 行为；不做 DirectShow 式的窗口管理。
- 扩展名选择未强制：移植按 content 资源目录解析（当前仅 `.mpg/.mpeg/.avi` 四个影片）；
  原生对其它扩展名失败，移植对缺失资源严格报错。
- `.movie2` 未实现；`id` 字段保存但不参与播放。
- 原生静默失败（文件缺失/不支持）在移植版是严格诊断。
- `t/f` 中断语义沿用静态推断：可跳过影片接受任意按键/左键；原生具体按键集合未逐一映射。
- 4K 源解码为 CPU 软解；长片首帧/高码率场景可能受解码性能影响，后续可接硬解或缓存。
