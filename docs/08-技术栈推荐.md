# 08 — 技术栈推荐（Linux 原生为主，兼容 Windows / macOS）

## 1. 结论先行

**推荐方案 A（首选）：C++20 + SDL3 + OpenGL 3.3 Core + FreeType + zlib + FFmpeg + miniaudio/stb_vorbis**
首先交付 Linux 原生程序；跨平台依赖为后续 Windows/macOS 留出空间，当前未完成这两平台验收。
不依赖 Proton/Wine，也不运行原 exe。已实现框架见 [NATIVE-RUNTIME.md](NATIVE-RUNTIME.md)。

选择依据（来自已完成的逆向结论）：
- 游戏是**纯 2D 视觉小说**：800×600 逻辑分辨率、PNG 图层/遮罩、Ogg Vorbis 音频、少量 AVI/MPEG 视频、TrueType 文字。
- 数据层已完全破解（PAZ = Blowfish/RC4/zlib，规格见 `PAZ_FORMAT.md`），脚本是**文本命令**（见 `02-SCRIPT-REFERENCE.md`），因此移植工作主要是"数据读取 + 2D 合成 + 文本排版 + 一个命令解释器"，不需要 3D 引擎、物理、场景编辑器。
- 这类需求用重型引擎收益低、约束大；用可移植底层库最直接，且 Linux 上"原生"体验最好（Wayland/X11 原生窗口、PipeWire/PulseAudio、整数缩放）。

**备选 B：Rust + winit/wgpu（或 macroquad）** —— 想要内存安全/现代工具链时选它，代价是视频/字体等生态要多花组装成本（见 §5）。
**备选 C：Godot 4.x** —— 最快做出"能玩"的跨平台版本，但文字排版/逐字显示/过渡保真度需要额外适配，视频需预转码（见 §6）。

## 2. 不推荐的做法
- **移植原 exe / 套 Proton、Wine、Box86**：你明确不要；且原程序是 Win32 DirectDraw7 + D3D9 + GDI 字体光栅器，跨平台成本高于重写。
- **Electron / Web（WASM）**：不是原生窗口/音频体验，逐帧 2D 合成与文件 IO 反而更麻烦，体积大。
- **Unity / Unreal**：对 2D VN 过重，Linux 原生打包与字体/GBK 处理都不省事。
- **pygame / LÖVE 直接做成品**：原型可以，但分发、字体排版（CJK 禁则/ruby）、视频解码能力弱。

## 3. 方案 A 库选型（逐项）

| 需求 | 推荐库 | 说明/备选 |
|---|---|---|
| 窗口/输入/手柄/HiDPI | **SDL3** | 备选 GLFW；SDL3 原生 Wayland/X11、Windows、macOS |
| 2D 渲染 | **OpenGL 3.3 Core** + 自写轻量 SpriteBatch（几百行） | 备选 SDL_Renderer（最快出原型）、sokol_gfx（macOS 可走 Metal） |
| 图像解码 | **libpng + libwebp** | PNG 开发回退；WebP 4×/8× 分发，KTX2 BC7/ASTC 安装缓存待接入 |
| 字体/文字 | **FreeType** | 内嵌 `MerriweatherMG.ttf`（拉丁）+ Noto Sans CJK SC（中文）；自写 CJK 禁则/排版 |
| 音频解码/混音 | **stb_vorbis** + **miniaudio**（单文件，跨平台后端） | 备选 libvorbis + SoLoud；需要 BGM 循环/交叉淡入、SE 多通道、voice 单通道 |
| 视频 | **FFmpeg（libavformat/avcodec/swscale）** | 4 个原视频离线重制为 H.264（建议 4K），保持时长/帧率；运行时 FFmpeg 解码 |
| 压缩 | **zlib** | 离线 PAZ/存档迁移；运行时随 libpng 使用，后续新存档按需使用 |
| PAZ 解密（离线） | 现有 Python `paz.py` / `paz_fast.py` | 运行时不带 Blowfish/RC4，不读 PAZ |
| 编码转换 | **iconv**（Linux/macOS 系统自带）/ Win32 `MultiByteToWideChar` | 离线 GBK/CP932 → UTF-8；运行时统一 UTF-8/UTF-32 |
| 构建 | **CMake Presets + 系统库 / FetchContent** | 当前 Linux 实现；缺少依赖时下载固定版本并校验 SHA-256，未来可接 vcpkg |
| CI | GitHub Actions Linux | 已添加核心/导入/软件 OpenGL 渲染检查；打包与其它平台矩阵待补 |
| 调试 UI | Dear ImGui（仅内部） | 正式 UI 需复刻原版坐标/状态，使用导入并重制的 sys 素材 |

## 4. 运行时架构（建议）
```
main
 ├─ core: 窗口/主循环(60Hz 逻辑帧 + 渲染插值)/输入/设置
 ├─ data: ContentManifest / PNG+WebP / AssetCache（仅从 content 读取）
 ├─ script: ScParser(文本→命令) / Vm(46 命令 + 变量/标签/调用栈) / 定时器
 ├─ scene: LayerStack(背景/立绘/overlay/screen/frame/text) + Transition(遮罩 alpha 合成)
 ├─ text: FontManager(FreeType) / GlyphCache / Layout(CJK 禁则/ruby/逐字) / Renderer
 ├─ audio: Mixer(BGM 流式循环/SE 通道/voice) 
 ├─ video: 全屏视频层(解码→RGBA 纹理→按帧推进)
 ├─ save: 新版本化存档；离线工具提供原版格式一次性迁移
 └─ ui: 标题/设置/存档/回想/图鉴/音乐（按原版证据复刻）
```
关键决策：
- **逻辑帧固定 60Hz**（`.wait` 毫秒 → 帧数换算，`.transition` 等按帧推进），渲染可 120/144Hz 插值；节奏与原版一致、过场可复现。
- **800×600 逻辑坐标**映射到物理像素的 4:3 视口；HD 图像与文字不先降至低分辨率。普通窗口选 4×，最大化/Borderless 选 8×，与屏幕分辨率无关。
- **资源按需加载**：只读 content，图像纹理缓存设预算；当前为同步 PNG/WebP 解码，后续补 KTX2 缓存与后台预取。
- **文字**：UTF-8 内部编码；FreeType 字形位图缓存（codepoint+px+样式）；自写排版（字宽=advance、CJK 禁则、行距、ruby 小字、逐字显示、颜色/描边）。
- **音频**：独立混音线程/回调，BGM 整曲循环、SE 多实例、voice 打断规则；`volumeBGM/SE/voice` 来自设置。
- **存档**：新版本化格式 + 原版一次性迁移（`SAVE_FORMAT.md`）；脚本定位用 script+行 ID（L0）为主锚点。
- **r18**：离线导入时保留补丁来源；运行时基于 content 资源映射与 `censored` 控制。预览框架仅支持显式 tag，不猜同名覆盖顺序。
- **汉化**：不需要原 DLL；离线 GBK→UTF-8 + 包内 CJK 字体 + 中文资源外置（UI 串/角色名/对话框文本）。

## 5. 备选 B：Rust 栈
`winit + wgpu`（或 `macroquad`）+ `png`/`image` + `swash`/`fontdue`（字体）+ `lewton`/`symphonia` + `kira`（混音）+ `ffmpeg-next` 或 `ffmpeg-sidecar`（视频）+ `flate2` + `blowfish`/`cipher` + `encoding_rs`（GBK）。
优点：内存安全、cargo 跨平台、并发好写；缺点：FFmpeg 绑定在 macOS/Windows 打包较麻烦，字体排版需自建（或 cosmic-text），生态比 C++ 分散。适合团队更熟 Rust、且能接受视频走"预转码 + 纯 Rust 解码器"的情况。

## 6. 备选 C：Godot 4.x（最快可玩）
优点：三平台导出成熟、UI/音频/存档/输入现成、开发速度最快。
代价：① 视频需把 4 个 AVI/MPEG 预转码为 Ogg Theora/VP9（Godot 原生支持）；② CJK 逐字显示/ruby/禁则需自写（TextServer 基础上）；③ PAZ/Blowfish/RC4 建议用 GDExtension(C++) 或离线抽取；④ 精细过渡/震屏/滚动可用 shader/节点实现，但与原版时序对齐要调试。
适合"先做能玩的验证版"，不适合追求逐帧保真。

## 7. 三平台兼容矩阵与注意点
| 平台 | 窗口 | 音频 | 打包 | 注意 |
|---|---|---|---|---|
| Linux x86_64 | SDL3 (Wayland/X11) | PipeWire/PulseAudio（miniaudio 走 ALSA/Pulse） | AppImage / Flatpak | 字体走内置，不依赖系统；Flatpak 需带 FFmpeg |
| Windows 10/11 | SDL3 | WASAPI | 便携 zip / Inno Setup | GBK 用 MultiByteToWideChar 或 encoding_rs；高 DPI 缩放 |
| macOS 11+ arm64+x86_64 | SDL3 | CoreAudio | universal .app + dmg | OpenGL 已废弃但可用；若担心可切 sokol_gfx/Metal 或 SDL_GPU；需签名+公证（可选自签） |

## 8. 许可证清单（分发时注意）
- zlib（zlib license）、libpng（libpng license）、FreeType（FTL/GPLv2 双许可，动态链接用 FTL）、SDL3（zlib license）、stb_vorbis（public domain/MIT）、miniaudio（MIT-0）、OpenSSL（Apache 2.0）、FFmpeg（LGPL 2.1+，需动态链接并声明）、Merriweather MG（OFL，可随包分发）、Noto Sans CJK（OFL）。
- 游戏原始数据与高清产物不入库；离线导入器读取用户自有素材，运行时只读取生成的 content，不要求原始目录或 exe/DLL。分发时按素材授权范围处理；当前预览包不作为公共分发资产。

## 10. 当前骨架入口

`src/app`（SDL3）→ `src/data`（content）→ `src/scene`（预览层）→
`src/render`（OpenGL）/`src/text`（FreeType）；`src/core` 提供坐标、档位、UTF-8、固定步长。
构建命令为 `cmake --preset dev && cmake --build --preset dev`。
运行前用 `python3 tools/prepare_content.py` 准备独立包，再运行 `./build/dev/ef_native --content content`。
详见 `NATIVE-RUNTIME.md`；原版 `.sc` 的基础执行/文字校阅另见 `SCRIPT-RUNTIME.md`，完整演出尚未接通。
