### 页号与槽号

构建函数、`FUN_004a7800` 和 `FUN_004a86a0` 一致将原版页号限制在 **0～9**。原始文件编号为 `page*10+cell`：第 0 页包含自动档 0、快速档 1～9；第 1～9 页为手动文件 10～99，即 **90 个普通槽位**。保存模式最低页为 1，读取模式允许 0 页。此前文档只根据命名推断普通槽位总数，不能把移植版 100 个普通槽位描述成原版观察结论。

构造证据 `ev_78032469cd9a50296c72dc07f5a7348f7073ada755120e17473e771f73b4a910`；最近保存页计算 `ev_5a9872318a774c93b9caa60282b0ad54b2874d2b8bbf0f45a7638fc88144940c`；页控制/提交证据 `ev_a8a1c7f01ca53289410b2e5eedf558898b1d563ead17241becb6d20420c80742`。

**移植决策**：保留已实现的 100 个普通槽位，扩为普通页 1～10。页 1 映射本工程槽位 1～10，页 10 映射 91～100；这是扩展，旧 `.sav` 文件编号不能直接作为本工程槽号。第 0 页 cell 0 暂为不可操作的自动档位置，cell 1～9 映射 q1～q9；自动存档尚未实现。快速页只供读取，快速写入仍由轮换存储接口执行。`native_pages` 和 `manual_pages` 在 JSON 中明确分开。
