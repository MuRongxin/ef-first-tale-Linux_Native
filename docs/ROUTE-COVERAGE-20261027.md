# 首次游玩路线验收（2026-10-27）

## 目标与入口

在 JSON 运行时上，从 `scr/test.sc` 的新会话开始，自动遍历实际出现的选项，沿 `.if`、`.goto` 和 `.chain` 执行到脚本结束；保存每条路径的选择、变量、跨文件序列、结束位置或第一个错误。源文件仅从 `content/` 读取。

这次覆盖的是**新会话可达的完整选择路径**，不是给 94 个脚本各自从零变量启动。章节间的好感度与其它局部变量会继续保留。读取既有存档后的入口、已通关标志激活的重玩分支、图鉴/回想的独立入口属于不同状态，不能用这份新会话报告代替。

## 验证层次

| 模式 | 实际执行 | 范围边界 |
|---|---|---|
| `control` | 生产 `ScriptLibrary` / `ScriptRuntime`：JSON 解码、两种 timing、变量、条件、跳转、选项、对白事件与结束 | 演出宿主命令显式模拟，不能证明场景和媒体实现正确 |
| `presentation` | 上述 VM，加生产 `Presentation`：场景参数、层布局状态、转场/特效/滚动/等待、真实音频解码和 mixer 的无声时钟 | 不启动 GPU 或音频设备，不解码高清图片像素，不绘制 UI，不解码电影 |

默认遇到电影会严格停止。只有显式传入 `--complete-movies`，才允许在真实宿主校验电影请求后模拟外部播放器完成；每次模拟记录在路径 `movies` 中，不管原 flag 是否可跳过，都不声称测试了用户跳过动作。它验证电影前后控制流衔接，不是视频播放验收。

场景时钟以每次更新 1 秒加速，文字即时展开；因此时序、语音播放长度和取景器计时不是原版逐帧对照。这份报告也不验收 `.ani` 的动画保真。

## 补丁策略

默认使用现有 `ScriptLibrary` 的命名空间解析。`--overlay-patches` 是审计工具明确选择的另一策略：对可被 `r18_scr/` 同名替换的程序，优先载入补丁，其它程序回退基础包；include 沿所选程序的原有解析规则展开。

该开关用于检验补丁剧情，**不代表生产程序已经实现成人补丁开关或确认了原版加载触发条件**，也不改变运行时当前的资源策略。报告记录 `overlay_patches`，两种策略不能混算成同一个运行配置。

## 工具与复现

```bash
cd "/home/lrxin/Ef_Linux/ef - the first tale"
cmake --preset dev
cmake --build --preset dev --target ef_route_audit

# 先检查控制流；默认入口为 scr/test.sc
./build/dev/ef_route_audit --content content --mode control --variant e \
  --report work/routes/control-e.json

# 接真实场景、音频宿主；电影明确模拟完成
./build/dev/ef_route_audit --content content --mode presentation --variant e \
  --complete-movies --report work/routes/presentation-e.json

# 补丁优先策略；j 变体
./build/dev/ef_route_audit --content content --mode presentation --variant j \
  --overlay-patches --complete-movies --report work/routes/presentation-patch-j.json
```

长时间全量检查建议使用 Release 构建以减少音频解码和参数验证开销；本机验证使用 `build/route-audit/ef_route_audit`（Release，`EF_BUILD_APP=OFF`）。四个配置分别是基础 e、基础 j、补丁优先 e、补丁优先 j，需分别运行，不能仅以一种变体代替其它配置。

默认限制为终止路径最多 256 条、选择深度最多 16、每条路径累计最多 1,000,000 次更新。可用 `--max-paths`、`--max-depth`、`--max-updates` 调整。返回码：0 为指定范围通过，1 为工具/包加载错误，2 为发现阻塞，3 为预算未完成；触及限制不会标记 PASS。

报告包含：

- 入口、timing、活动索引、补丁策略、范围声明及限制；
- 每条路径的选择序列、对白计数、文件序列、结束位置、局部/全局变量、诊断及电影模拟记录；
- 尝试执行过的物理指令位置、实际进入的脚本、条件跳转两侧和跨文件边；失败指令位置属于“尝试”，不代表成功；
- 未进入的脚本清单。菜单调用脚本、回想脚本、未选中的基础/补丁副本以及其它入口会留在清单中，不将它们记成剧情缺失。

`<report>.paths.jsonl` 每完成一条路径就追加一行，可在全量结束前检查；只有最终 JSON 的 verdict 才是整次审计结果。工具不会把运行报告、游戏剧本和资源加入 Git。

## 工程保障

选项处复制 VM 与场景宿主状态，随后重绑当前分支的回调；不会靠重置变量从某个中间文件开始。mixer 的分支副本共享不可变 PCM，播放位置、淡化包络和各通道活动状态独立，复制时锁定源 mixer。

真实解码缓存仅由离线审计器注入，缓存自身上限 128 MiB，活动 mixer 引用的 PCM 另外持有；不改变生产播放的默认解码方式。

自动测试使用合成 JSON 包，覆盖变量隔离、条件两侧、跨脚本延续、严格错误、预算不足、显式补丁策略，以及电影必须显式模拟且不能声称解码。现有音频测试补充 mixer 状态复制独立性。
