# content — 运行时数据

运行 `python3 tools/prepare_content.py --all --game-root '/path/to/game'`，从本地素材、
高清产物、原版音频和中文字体准备独立资源包。此目录中只有本 README 入库，
所有游戏素材、字体副本与生成清单均忽略。

`ef_native --content content` 只从该目录加载素材/场景/字体，不访问原始游戏或 `assets/`。
复制整个目录即可搬迁数据；不要用指向包外的软链接代替导入。

默认包含 1× 开发回退及已有的 4×/8×；`--hd-only` 不带 1×。
导入器按内容哈希存放图片/剧本/索引 blob，原音频在 `audio/`、视频在 `video/`，
最后原子替换 `manifest.json`。全量包通过 `script_index`、`resources`、`import_report`
引用同一批次的不可变索引。重复导入会验证并复用已有 blob，不建立素材硬链接。
旧 blob 暂不自动清理，避免运行中的进程失去引用。

资源目录按类型和文件名解析，处理 ASCII 大小写，优先匹配完整归档文件名。
只有没有精确匹配时才尝试 `.png-`/`.png.tmp` 兼容别名，避免把不同 UI 状态合并。
补丁资源仅在调用方明确启用时覆盖对应归档类别；未开启时排除补丁独有资源。
同名、同源哈希的资源可以共用解析结果，同名异源则报歧义。
`.ani` 尚未转换为运行时动画，不会伪装成已支持的资源。

运行时按需解码，超过当前纹理/内存预算时回退低档；KTX2 缓存与分块纹理仍待实现。
`--validate-content` 是完整解码检查，超出 512 MiB 解码预算的档位会报错。
`--audit-resources` 用于检查资源映射和包内文件，不执行全量像素解码。
窗口中的 R 可重载图像预览，剧本会话需重启。

构建与准备数据的命令见 [项目 README](../README.md)。
